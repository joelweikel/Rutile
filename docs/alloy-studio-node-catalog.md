# Alloy Studio node catalog and data contracts

These are the planned graph contracts. Where an operation wraps existing code, the catalog names the existing method and its limits. Models added later must publish their parameter definitions and applicability before the editor offers them as available. [Workflow and implementation plan](alloy-studio-workflow-plan.md)

## Values and pins

Each pin type has a value kind, shape, and domain qualifier. A **Color** is one qualified value, a **List of Color** has list shape, and **Material Color** is a record that associates colors with specific phases and conditions. A list of colors can become a palette. A conversion to Material Color needs phase IDs and appearance conditions.

| Family | Types and required qualifiers |
| --- | --- |
| Simple | `Number` (finite, dimensionless), `Integer` (with bounds where applicable), `Boolean`, `Text`, `Choice<enum>`, `Element` (element symbol), `PhaseName` (raw text for lookup or display), `Color` (space, channels, white point where applicable), `Image` (width px, height px, color space, alpha mode, pixel format or image artifact ID) |
| Quantities | `Quantity<kind>` with value, unit, and optional uncertainty. Use K for absolute calculation temperature, s for time, Pa for pressure, and m for length. Label common display units such as °C, min, μm, MPa, GPa, and g/cm³. Distinguish absolute temperature from temperature difference. |
| Fractions | `Fraction<basis>` with a value on 0–1 and a declared basis when applicable. Composition supports mass or atomic basis. Phase amount supports mole, mass, or volume basis. Spatial area, volume, and population number fractions remain distinct. |
| Collections | `List<T>` with ordered, typed items. `Table` with column names, types, units, and rows. `Series<X,Y>` with axis types and sample order. `Distribution` with quantity kind, bin edges or samples, weights, weighting basis, and normalization. `SpatialField<T>` with coordinate frame, dimension, geometry or array, origin, spacing or mesh, unit, and field semantics. |
| Domain records | Identified structured data such as Composition, Phase Set, Material State, Tracer Diffusivities, Elastic Tensor, or Material Color. Offer named field outputs and preserve the record's context and provenance. |
| Evidence | `SourceRef`, `Provenance`, `Issue`, and `Coverage` carry source documents, validations, diagnostics, and field-specific coverage. They can be inspected or exported as structured data. |

### Pin shape and color

Use gray for raw Phase Names, violet for Phase Records and Phase Sets, amber for Composition and schedules, blue for source files, rose for Microstructure and spatial fields, silver for references, green for property results, and cyan for image and appearance pins. Use named labels plus a single circle for a value, stacked circles for a list, and a diamond for an ordered path or series. Use the same family color for a value and a collection of it. A pin's label and type qualify the exact relationship. Density and yield strength can both be green while remaining distinct property kinds.

Promote a unit-compatible quantity to the expected display unit through an inspectable conversion. A composition-basis conversion takes element masses. Converting phase moles to volume takes phase-specific molar volumes. Use an explicit Select or Assemble for an item/list conversion that requires a choice. Keep a Phase Set's original total and selection context when splitting it.

## Shared fields

Variables in backticks are proposed schema names. A node may expose several fields as an expandable record pin. Optional fields carry an explicit missing reason when a model requests them. Version the model-specific parameter schema and record each parameter's unit, source, allowed range, and role.

| Record | Fields |
| --- | --- |
| Source Ref | `source_id`, `role`, `filename`, `sha256`, `size_bytes`, `format`, `version`, `citation`, `license`, `catalog_id` or artifact ID, and optional stable external record ID and data release. Link converted artifacts to original hashes and conversion reports. |
| Conditions | `temperature_k`, `pressure_pa`, optional `elapsed_s`, `event_index`, and `stage`. Test and surface conditions add their own environment, loading, and observation fields. |
| Provenance | Operation ID and version, source refs, solver/package versions, input artifact IDs and hashes, normalized settings, transformations, assumptions, method validity bounds, creation time, and origin of each value. Use measured, calculated, sourced, or assumed as origin, with calibrated or screening estimates labeled where applicable. |
| Issue / Coverage | Issue code and severity, related node/pin/phase ID, reason, and action to take. Coverage stores required and supplied records, their status, covered and omitted amounts and basis, and the reason for each gap. |
| Composition | `base_element` when using a balance, `input_basis`, `input_amounts` by element, calculated balance, and normalized `atomic_fractions` when derived. A range also has `minimum`, `maximum`, optional `step`, and a basis for each variable. Absolute compositions record any normalization. |
| Thermodynamic Assessment | Source Ref, declared elements, active components, model signatures, structural constraints and documented applicability. Store model identifier, active constituents, site ratios, ordering links, and relevant reference-state evidence. |
| Mobility Data | Source Ref, associated assessment hash or pairing evidence, supported solver phases and diffusing species, and compatibility report for the requested phase and composition. |
| Physical Data | Source Ref, declared parameter kinds, parser/conversion version, available phase-model mappings, and source description. Initial supported kind is MatCalc DP density. |
| Raw Phase | `instance_id`, `solver_phase`, `assessment_sha256`, `model_ref`, calculated `composition_atomic_fractions`, `amount` and `amount_basis`, and available ordering or site-occupancy evidence. A manually entered name can start as a raw label with no invented composition or fraction. |
| Phase Definition | `canonical_id`, `structure_kind`, optional prototype, space group, unit cell and sites or CIF ref, ordering state, source aliases, match status, evidence, and independent property references. Represent liquid or noncrystalline identity explicitly. Maintain more than one sourced property record when its conditions or methods differ. |
| Phase Instance | Raw Phase fields plus optional `phase_definition_id`, `resolution_status`, and attached property records applicable to that instance. Store amount and actual composition on this record. Several instances can share a phase definition or solver name. |
| Phase Set / Phase Path | Phase Set has `phase_set_id`, `conditions`, `composition_id`, `assessment_ref`, `phases`, shared fraction basis, phase and elemental balance residuals, provenance, and optional parent set, selected IDs, excluded IDs, and included/omitted amounts. Phase Path has ordered state IDs, stage and event labels, and available time or temperature coordinates. A sampled equilibrium path carries elapsed time only when specified. |
| Processing Schedule | `route`, initial and target conditions, `events` in order, and notes. Each event records its kind, setpoint, time or rate if supplied, and operation-specific controls. Preserve requested and realized histories where both are available. |
| Microstructure | State and phase IDs, `grain_size_distribution`, `precipitate_populations` by phase, texture or orientation distribution, matrix solute composition, dislocation density (m⁻²), morphology descriptors, porosity when supported, and optional phase/grain/orientation fields. Each precipitate population can carry size distribution, number density (m⁻³), volume fraction, spacing, shape, and spatial field. Mark spatial data as measured, modeled, or schematic. |
| Material State | `state_id`, optional `parent_state_id`, name, composition, conditions, phase set, chronological history, optional microstructure, attached property results, and provenance. An equilibrium-only state can be saved with unresolved microstructure fields. |
| Reference / Measurement | `property_kind`, value or artifact, unit, uncertainty, material/phase ID and composition, structure, sample and processing condition, measurement or calculation method, temperature and pressure where relevant, test conditions, citation, version/checksum, and applicability evidence. |
| Property Result | `property_kind`, numeric, tensor, or series value, unit, status, covered phase or Material State, test/observation conditions, method, assumptions, uncertainty, applicability, provenance, and issues. Keep a phase estimate, subset estimate, and complete alloy result identifiable. |
| Test Conditions | `temperature_k`, `strain_rate_s_1`, loading mode, test method, direction, specimen form and dimensions, and optional proof-strain offset. For indentation, include hardness scale, load N, dwell s, and any method parameters. |
| Flow Curve / Elastic Tensor | Flow Curve specifies true stress vs. true plastic strain, or an explicitly different axis definition, test conditions, and named constitutive model and parameters. Elastic Tensor includes stiffness or compliance representation, unit, axes/frame, ordering convention, and applicable phase or state. |
| Tracer Diffusivities | Selected phase instance and original solver model, actual composition, temperature K, pressure Pa, per-element coefficient in m²/s, TDB and DDB refs, compatibility and conversion reports, and whether the result is for a reference-only phase. |
| Optical Data / Material Color | Optical Data holds wavelength nm plus reflectance fraction, or wavelength and `n`/`k` or complex dielectric data, with geometry, surface finish, polarization where relevant, and provenance. Material Color maps phase instance IDs to Color records, with illuminant or spectral power distribution reference, observer, white point, surface condition, and missing coverage. |
| Etchant / Surface State | Etchant records bath constituents and concentrations with units, pH where applicable, temperature K, exposure s, immersion or application mode, agitation/flow assumptions, and source. Surface State carries starting state and recipe IDs, height or removal-depth field in m vs. time s, reference geometry, optional film or appearance data, method provenance, and issues. |
| Design Space / Objectives | Variable IDs and input locations, bounds or discrete choices, units and bases, composition balance constraints, property kind, minimize/maximize or limit, target, unit, feasible condition limits, and evaluation budget. |

## Source and workflow inputs

### MatCalc and manual files

Expose file nodes as inputs to the source group. Import through the local catalog or pick an existing file by immutable ID. Use `.tdb` and `.tbd` for thermodynamic assessment selections, `.ddb` for the named MatCalc mobility companion, and `.pdb` for MatCalc physical data in this workflow. Interpret contents and declared role before binding a file.

| Node | Inputs and settings | Outputs and validation |
| --- | --- | --- |
| **Source File** | Local import or catalog entry, expected role, optional description. | Source Ref and inspection report. Pin original bytes by SHA-256. Present switchable candidate files if identical filenames have different contents. |
| **MatCalc Sources** | `family`, optional wired **Thermodynamic File**, **Mobility File**, **Physical Data File**, and **Use Local Physical Data**. Inspector also shows the resolved filenames and paths. **MatCalc Al** is a named preset of this node. | **Assessment**, **Mobility Data**, **Physical Data**, and **Source Report**. The assessment is required for equilibrium. Optional companions can be absent with explicit reasons. Named preset files are supplied as visible defaults for unwired pins. |
| **Manual Sources** | Required **Thermodynamic File** and optional **Mobility File**, **Physical Data File**, and documented pairing evidence. | The same typed outputs. A manual TDB has no automatic MatCalc mobility pairing. Explicit mobility pairing is future work and needs source/model compatibility validation. Offer the configured physical data separately and run its density checks for each phase. |
| **Check Assessment Coverage** | Assessment, active components or Composition, temperature range K, pressure Pa, phase policy, optional applicability records. | Declared availability, applicable evidence, unknown/unassessed interactions, and named phase-compatible options. Use documented coverage data when present. |
| **Import Rutile File** | Validated `.rutile` or equivalent JSON document, imported attachments by checksum. | Workflow, Phase Set, or Material State as appropriate. A dropped Phase Set or Material State creates an input node. Missing raw sources affect recalculation while saved, validated values remain inspectable. |
| **Import Measurement / Spectrum / Microstructure** | File ref, schema/column and unit mapping or image geometry, sample identity, provenance, and relevant conditions. | Typed reference, series, image, or spatial field plus import errors. Preserve original order for time and tensile curves. |
| **Attach Reference / Enter Reference Data** | Phase or state ID, typed value or file, units, method, source, validity conditions, and origin. | Updated phase or material record carrying the reference and any applicability gaps. User edits produce a derived record. |

| MatCalc Mg | `mg/mc_mg_v202.tdb` | `mg/mc_mg_v202.ddb` |

Honor `RUTILE_DATABASE_ROOT` as a replacement source root and `RUTILE_PHYSICAL_DATABASE` as the physical-data override. Show when an expected file is missing in the active root. Wired file inputs are explicit selections. Recheck or clear an inherited mobility binding if the thermodynamic source changes. Validate the phase, active constituents, sublattice structure, function conflicts, and applicable kinetic parameters before attaching mobility. ## Scientific nodes

### Equilibrium, density, elasticity, and diffusion

| Node | Required inputs and settings | Results and availability |
| --- | --- | --- |
| **Equilibrium at Point** | Assessment, Composition, temperature K, pressure Pa, phase policy and explicit permitted phase selection if applicable. Retain solver settings and mass-balance tolerances. | Phase Set, Gibbs energy (J/mol), check residuals, and solver/model provenance. |
| **Equilibrium Along Schedule** | Assessment, Composition, Processing Schedule, phase policy, cooling point count, and solver settings. Map to the existing processing request during migration. The Fe–Fe₃C policy stays limited to its reviewed Fe–C source and composition constraints. | Initial, melt if applicable, and final Phase Sets, Phase Path, stage issues, and checks. Preserve melt preflight and report how equilibrium setpoints were chosen. Time-dependent state changes use separate kinetic nodes. |
| **Binary Phase Diagram** | Assessment, two elements, composition and temperature bounds, Auto/Manual range, pressure, temperature-point and sample-check settings, worker count. | Structured diagram, method and fallback reasons, partial regions, counted checks and coverage, and reusable phase inspection. Wrap the existing binary job when integrating it into the canvas. |
| **Phase Molar Volume** | Phase Instance and its condition, compatible Physical Data or a reviewed reference/model, assessment for DP, atomic molar masses from the pinned assessment or an explicit source. | Density or molar volume on a documented molar basis, contribution details, method, and coverage. Transfer a reference's molar volume with its chemistry and approximation recorded. |
| **Density** | Phase Set, explicit atomic molar masses, evaluated phase volumes or Assessment and Physical Data to evaluate DP, optional accepted phase references, and an explicit approximation policy. | Per-phase density, phase molar masses and volumes, complete alloy density when covered, volume fractions, and covered/omitted amounts. A filtered set yields a subset result. |
| **Elastic Moduli / Poisson’s Ratio** | Phase Set, phase volume fractions, applicable stiffness tensors or elastic model, averaging method and assumptions, and optional test temperature and orientation. | Young's, bulk, and shear moduli in Pa with convenient GPa display, Poisson's ratio, bounds, and coverage. With the existing isotropic model, retain volume-weighted Voigt/Reuss/Hill values and any explicitly requested screening output. |
| **Tracer Diffusivity** | Assessment, compatible Mobility Data, selected Phase Set and optional phase instance ID, phase composition, temperature K and pressure Pa from that state, and active components. The initial auto selector chooses the largest eligible final solution phase as in current processing. | Per-element tracer coefficients (m²/s), selected phase, model and conversion report, and missing or invalid data reason. Offer the nominal-composition phase-restricted fallback as an explicitly labeled reference-only result. |

For automatic density evaluation, try the compatible local MatCalc `DP` model first, followed by applicable reference volume data. Show the chosen source for each phase. DP uses the solver phase composition and temperature, explicit endmembers, and supported interactions. Its current scope is supported substitutional models, with any allowed disordered parent approximation labeled. Report missing explicit endmembers, unsupported sublattices, or out-of-range temperature. Exclude generic DP wildcard defaults. Save `rho_i` in kg/m³, `M_i` in kg/mol of atoms, `V_i` in m³/mol of atoms, and phase mole fraction `f_i`, with conversion at the existing adapter boundary. With compatible atomic molar masses and volumes, bulk density is `sum(f_i * M_i) / sum(f_i * V_i)`. Report optional screening separately with its approximation. [Local DP density and reference methods](processing.md#local-matcalc-dp-density-adapter)

The existing Kawin path uses the original solver phase key and compatible mobility functions to evaluate tracer coefficients in a solution phase. The current automatic candidate list is `FCC_A1`, `BCC_A2`, `BCC_B2`, and `HCP_A3` with available mobility parameters. The DDB adapter expands allowed wildcard fallbacks and prefers explicitly matching endmembers. A structure assignment contributes identity evidence while the original TDB/DDB pair supplies the kinetic model. Scope the node to the connected state's composition, temperature, and pressure. For the current code path, capture the discrepancy when an anneal or quench follows cooling and its temperature differs from the original cooling target. Later models of interdiffusion or precipitation declare their own kinetic inputs. [Kawin processing adapter](../backend/src/rutile3/engines/processing.py)

### Processed states and mechanical properties

| Node | Model inputs and variables | Result |
| --- | --- | --- |
| **Scheil Solidification** | Assessment, bulk composition, initial liquid state, pressure Pa, temperature step K or convergence settings, phase policy, liquid mixing and solid diffusion assumptions, stopping criterion, and model version. | Solidification path, liquid and solid amounts/compositions, available segregation distributions, and a derived as-solidified state where the transfer is defined. |
| **Diffusion / Homogenization** | Starting state or spatial composition profile, assessment and compatible mobility/transport model, geometry/length m, boundary conditions, temperature vs. time, and solver tolerances. | Time-dependent concentration profiles, phase redistribution within model scope, and the derived state. |
| **Precipitation Kinetics** | Starting matrix and solute content, candidate phases, thermodynamics and compatible transport, temperature vs. time, initial populations, nucleation site density, interfacial energy J/m², shape/coherency parameters when required, and time/size grid settings. | Matrix solute evolution, precipitate distributions, fractions, spacing, and state vs. time. |
| **Grain Growth / Recrystallization** | Starting grain distribution and deformation state, time–temperature path, applicable boundary mobility/driving force parameters, and pinning particle data when modeled. | Grain distributions, recrystallized fractions, and texture when supported by the model. |
| **Deformation / Recovery** | Starting state, reduction or strain path, temperature, strain rate, initial texture/dislocation state, and applicable storage and recovery parameters. | Updated dislocation state, texture, grain shape, and other modeled fields. |
| **Fit Flow Curve to Test** | Engineering tensile trace with units, specimen and test conditions, elastic fit or supplied modulus, valid fitting range, and constitutive model. | Measured metrics, fitted parameters, residuals, and material-condition applicability. |
| **Predict Flow Curve** | Processed Material State, active phases and mechanisms, elastic constants, slip geometry, Burgers vector length, applicable solid-solution, grain-boundary, precipitate and dislocation parameters, hardening law, test temperature/strain rate, and strain domain. | True stress vs. plastic strain and labeled mechanism contributions or missing inputs. |
| **Yield Strength / Hardness / Tensile Peak** | Flow Curve and test conditions. Yield takes the proof offset or specified definition. Hardness takes the scale, representative strain and constraint factor as applicable. Tensile Peak takes the tensile model, strain coverage, and a damage/fracture result if premature failure is modeled. | Yield or UTS in Pa/MPa and test definition, hardness scale and method, and limits or failure mode for the reported peak. |
| **Fracture / Damage** | Material and flow response, crack/flaw geometry and dimensions, specimen geometry, loading, and applicable condition-specific toughness or calibrated damage parameters. | Fracture or damage criterion, failure load or simulated damage evolution, and model limits. Any independent toughness prediction needs a validated toughness model. |

Use one physically justified flow response for yield, hardness, and peak load where its assumptions apply. Calibrate parameters against measured conditions and reserve independent chemistry, route, or condition benchmarks for transfer checks. [Mechanistic property specification](mechanical-properties.md)

### Appearance, magnetism, comparison, and design

| Node | Model inputs and variables | Result |
| --- | --- | --- |
| **Phase Reflectance / Polished Color** | Phase Set/instances, measured reflectance or validated optical model with phase-matched optical constants, wavelength grid nm, surface finish, viewing geometry, illuminant and observer. A first-principles optical provider additionally requires an applicable phase structure, occupation/order, and electronic-structure settings. | Per-phase reflectance, CIELAB and Material Color, calculated or measured origin, and coverage. Render a polished spatial image only with spatial phase data. |
| **Reflectance to CIELAB** | Wavelength/reflectance samples, illuminant spectrum, observer color-matching functions, spectral overlap, and reference white. | `L*`, `a*`, `b*`, optional display swatch and gamut information, and conversion provenance. |
| **Simulate Etch / Render Reflected-Light Image** | Phase Set, etchant and exposure, actual or modeled spatial microstructure for relief, appropriate dissolution rates or calibrated kinetic laws, bath transport and film parameters where applicable, optical data, and microscope illumination/geometry for rendering. | Surface State with depth vs. time where supported, optional Material Color/appearance, image output through the renderer, and missing data report. Distinguish modeled relief from a schematic palette. |
| **Corrosion Rate** | Material State or characterized surface, environment and time, pH and electrolyte chemistry where applicable, temperature, electrochemical or measured kinetic parameters, and exposed geometry and coupling assumptions. | Rate or localized damage metric with units, environment, method, and coverage. Etch predictions require kinetics for the specified bath. |
| **Magnetic Property** | Specific property kind, the applicable phase or processed state, phase magnetic parameters, temperature K, field strength/direction and, for microstructure-sensitive properties such as coercivity, the required domain/grain information and model. | Named property, such as coercivity in A/m, and the conditions and evidence defining it. Start with a specific validated model and dataset. |
| **Compare Property / Check Limits** | Typed Property Result(s), reference collection or explicit target/limits, comparable conditions, units, distance/tolerance criterion, and optional acceptable origins or ranges. | **Summary Text** and structured comparison rows with matched property, benchmark, condition, normalized value, difference, source, and scoped warnings. |
| **Compare to Measurement** | Predicted result or series, independent measurement, matching material condition, unit/axis mapping, and metric or tolerance. | Residuals, matched range, benchmark outcome, and any context mismatch. |
| **Composition Sweep / Processing Sweep** | Candidate ranges or schedules, a selected evaluable workflow, measured or modeled limits, max evaluations, worker budget, and optional seed for stochastic methods. | Candidate results table, infeasible/unavailable reasons, and referenced run artifacts. |
| **Optimize Alloy** | Design Space, objective and limit declarations, referenced workflow and outputs, solver settings, stopping condition, evaluation budget, and optional random seed. | Ranked feasible results or a Pareto set for multiple objectives, per-candidate provenance, and reasons for excluded candidates. |

**Compare Property** normalizes units and checks the property kind before comparing values. For example, a density of **21 g/cm³** can be compared to rhenium at **20.8 g/cm³** and platinum at **21.5 g/cm³** using room-temperature elemental references. A yield strength of **2 GPa** can be compared to a particular heat-treated maraging 300 measurement with the test condition shown. Warn when **100 GPa** exceeds the selected bulk-alloy benchmark set and suggest checking MPa versus GPa. Keep that warning scoped to the selected data. To display the sentence on a backdrop, connect **Summary Text → Text to Image → Preview**. [Rhenium](https://periodic-table.rsc.org/element/75/rhenium) · [Platinum](https://periodic-table.rsc.org/element/78/platinum) · [Maraging 300 tensile measurements](https://www.scielo.br/j/mr/a/K4sBsJyjnyDMRcgFSR9mxKx/?format=html&lang=en)

Use official CIE tables for the colorimetric conversion. Benchmark a known phase spectrum before adding arbitrary alloy color prediction. For etching, start with one alloy and bath and compare modeled surface relief to measured profiles and a matched image where available. These optical, etch, corrosion, and magnetic nodes are planned scientific work.
